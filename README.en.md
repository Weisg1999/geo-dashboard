# GeoDash v2 · 3D Project Distribution Dashboard

[中文 README](./README.md)

A rebuild that combines the best of two projects: **the globe visuals of [vasturiano/three-globe](https://github.com/vasturiano/three-globe)** (night-lights texture, atmosphere glow, animated spherical polygon transitions, star field) + **the complete dashboard feature set of v1 (geo-dashboard)** (province → city → project three-level drill-down, hover/selected/dimmed tri-state, search, camera fly-to animations, panel linkage, nine-dash line & South China Sea islands compliance elements, adaptive quality).

Zero build step, zero runtime dependencies: three, three-globe and all 31 transitive packages are vendored into `vendor/` — works fully offline on intranets.

## Quick start

| Method | Steps | Notes |
|---|---|---|
| Double-click `启动大屏.bat` (launcher) | Starts a local server and opens the browser automatically | Tries Python → py → npx → built-in PowerShell server (`server.ps1`, zero-dependency fallback) in that order |
| Manual server | `python -m http.server 8126`, then visit `http://localhost:8126/index.html` | ES modules are subject to CORS, so **do not** open `index.html` directly via file:// |
| Single-file build | Double-click `GeoDash-v2-单文件版.html` | Generated by `构建单文件版.bat`; opens directly from file:// with code, data and textures all inlined |

## Editing data day-to-day

Only two files to touch; refresh to take effect:

- `js/config.js` — company name, titles, HQ coordinates, status/type colors, data source URLs, `showArcs` (flight-line toggle, off by default)
- `js/projects.data.js` — project array (`id/name/province/city/lon/lat/type/status/amount/date/address`)

The province-level basemap GeoJSON is cached at `vendor/geo/100000_full.json` (DataV areas_v3); city-level drill-down data is fetched from DataV on demand and stored in localStorage.

## Pitfalls log (verified during v2 development — read before modifying)

1. **Accessors must return CSS color strings.** three-globe parses `polygonCapColor` etc. with d3-color (`color(str).opacity`); returning a `THREE.Color` object throws `Cannot read properties of null`.
2. **Never override `polygonCapMaterial` with a custom material.** The layer guards with `!capMaterial && capColor`: once a custom material is provided it skips per-polygon color assignment and every plate turns black. three-globe 2.45's default materials are already per-polygon unlit `MeshBasicMaterial`s — exactly what v1's "unlit prevents block lightning" conclusion requires.
3. **`polygonAltitude` is a fraction of the radius, not an absolute unit.** Porting v1's `1.2` (1.2% of R=100) verbatim floats plates to 2.2× the radius and traps the camera inside them.
4. **Duplicate THREE instances render silently nothing.** Each three-globe layer evaluates `window.THREE ? window.THREE : {private imports}`. Without `window.THREE`, some classes come from the `three/webgpu` bundle and render invisibly under the core `WebGLRenderer` — no errors. `three-global.js` must be imported before `globe.js`.
5. **The lon-lat ↔ vector convention must match three-globe's** (`polar2Cartesian`: `phi=90-lat, theta=90-lng`). v1's custom convention differs by a 90° rotation about Y; mixing them misplaces markers/chips/camera relative to plates (plates appear to "vanish"). Use `util.lonLatToVec3` / `util.vec3ToLonLat` exclusively.
6. **GeoJSON winding.** three-globe follows the D3 spherical convention (outer ring clockwise) while standard GeoJSON (RFC 7946, e.g. DataV) is counter-clockwise; feeding it raw triangulates the *complement* and blankets the whole sphere. `util.normalizeFeature` fixes winding via signed area.
7. **The globe sphere defaults to a lit `MeshPhongMaterial`** — pure black in a lightless scene. `globe.js` converts the texture into an `emissiveMap` so it outputs true colors while the scene stays light-free.
8. **No bloom.** The root cause of v1's "block lightning" was real-time lighting luminance crossing the bloom high-pass threshold (see the v1 repo's POSTMORTEM.md). v2 deliberately has no post-processing chain; hover brightening uses an HSL lightness multiplier capped at 0.62 instead of lerping toward white (which washes deep blue into gray).
9. **The built-in `polygonStroke` is drawn at the base radius** and gets covered by elevated plates — city boundaries were invisible when drilling down. Since v2.1 every feature gets its own "cap-top glow boundary" (`LineSegments` built on the unit sphere, scaled per frame to ride the plate's current altitude, additive blending), for both provinces and cities; caps also became slightly translucent (rgba) so night city lights bleed through for extra depth.
10. **Project markers are glow dots** (halo + core + pulse ring sprites): v2.1 removed v1's billboard light-pillar shader; `markerPick` ray-tests only the two sprites.

## Single-file build

`tools/build-singlefile.py`: esbuild bundles `main.js` with all ESM dependencies into one IIFE → inlines the classic scripts (config/data/taiwan/frame-ticker) → injects `window.__EMBEDDED__` (province GeoJSON) and data-URL textures → strips the importmap and the file:// guard. Output ≈ 4 MB. City-level data is too large to inline, so drill-down in the single-file build still needs network access.

## Label placement (v2.1)

Province chips and city labels anchor at each polygon's **pole of inaccessibility** (a self-implemented Mapbox `polylabel`): guaranteed inside the plate and visually centered — outer-ring centroids drift offshore or outside the boundary for elongated (Inner Mongolia, Gansu) or island-heavy (Guangdong, Fujian) regions. Floating height was lowered (1.09R → 1.05R) to reduce edge-of-globe parallax, and a spherical collision pass nudges crowded chips apart along the great circle, reverting any move that would leave the province polygon.
